# 逐回合接战决策评分

## 评分目标

评分回答的是“做决定时的可观测条件有多危险”，而不是“玩家最后死亡，所以决策一定错误”。
系统目前只评价死亡前的接战快照，不评价所有存活或未接敌决策。

## 输入信号

- 接战分类：孤立推进、孤立接触、附近支援、支援不确定、最后存活；
- 最近队友距离；
- 死亡前五秒移动距离；
- 五秒内团队有效闪光；
- 双方存活人数；
- 死亡后是否完成补枪。
- 回合已进行时间与炸弹安放/拆除/爆炸状态；
- 活跃烟雾数量，以及烟雾是否落在玩家与最近队友的二维连线附近。
- 击杀者位置、击杀距离与十秒窗口内首次造成伤害的时间；
- 附近队友是否朝向击杀者，以及队友到击杀者的线路是否被活跃烟雾遮挡。

不同分类先获得基础风险，再由其他条件加减分，最终限制在 0—100：70 以上为高风险，
40—69 为中风险，低于 40 为低风险。缺少队友距离会降低判断置信度。

评分前会先生成结构化 `RoundSituationState`，统一描述回合阶段、人数关系、支援准备、炸弹目标、
移动节奏和信息完整度。当前已区分 T 方下包后无收益前压、CT 回防的必要争夺空间、T 方后段未下包
的时间压力，以及炸弹已经结算的低置信度快照。

## 重要边界

- 死亡不会直接加分；
- 最后存活者不会因为无队友补枪被判高风险；
- 队友空间距离近只代表“可能支援”，不能证明视线畅通；
- 死亡后成功补枪、接战前有效闪光会降低风险；
- 烟雾遮挡是基于烟雾中心与二维连线距离的几何代理，不等于真实视线；
- 当前仍未加载地图墙体碰撞，因此不能确认队友是否真的看得到同一目标；
- “补枪准备队友”只同时满足距离、朝向和烟雾代理，不代表一定能穿过墙体看到击杀者；
- 炸弹与回合时间用于解释局势，尚不在缺少人工标注时大幅改变风险分。

## 评测方法

第一版评测集包含 14 个手工构造的边界场景，检查风险等级、分数范围、队友朝向和数据缺失时的置信度。
结果同时报告高/中/低风险分层准确率、分数区间命中率和置信度准确率。
它用于防止修改公式后出现明显逻辑回退，不等价于真实比赛准确率。

下一版应邀请有经验的玩家在不看系统输出的情况下标注真实回合，并拆分开发集与盲测集；
比较系统与人工标注的等级一致率，同时记录争议样本，避免仅为已有公式构造“必然通过”的测试。

## 真实 Demo 覆盖审计

```powershell
python -m chapter07_cs2_coach.situation_cli `
  --demo-dir ".agent_data\demos" `
  --player-steamid "7656..." `
  --output ".agent_data\audits\situation-coverage.json"
```

报告聚合阶段、人数、支援、炸弹目标和移动节奏，并统计信息完整度。若大量接战缺少回合时间、支援条件，
或落在炸弹已经结算的事件窗口，报告会明确告警，避免评分在缺失数据上表现得过度自信。
