# Demo 数据质量门禁

系统给出训练建议以前，必须先确认解析数据足以支持结论。`quality_cli` 会为每场比赛检查：

- 击杀交火覆盖率：回合击杀数是否都能找到对应交火片段；
- 死亡交火与局势快照覆盖率：每次死亡是否都有可追溯上下文；
- 重复交火率：避免同一事件重复计数后放大习惯；
- 未知点位率：判断地图级建议是否有足够位置证据；
- 关键上下文缺失率：距离、朝向与支援准备度代理是否完整；
- SteamID：跨场去重和同名玩家识别是否可靠。

运行示例：

```powershell
python -m chapter07_cs2_coach.quality_cli `
  --demo "D:\demos\match-1.dem" `
  --demo "D:\demos\match-2.dem" `
  --player-steamid "7656..." `
  --output ".agent_data\quality\batch-v1.json"
```

也可以用 `--demo-dir` 扫描目录第一层的所有 `.dem`。重复比赛按 `match_id` 去重，解析失败会单独
列出，不会被算成玩家表现。

门禁有三个结果：

- `pass`：所有检查通过，可以进入画像与建议环节；
- `review`：存在轻度缺失，建议可以展示，但必须降低置信度；
- `fail`：关键事件覆盖不足或数据异常，不应根据该场更新长期玩家画像。

字段“不适用”不会算作缺失。例如玩家已是最后存活者时没有队友可计算支援准备度，此时空值是正确事实。

质量分只是工程可观测性指标，不是模型准确率，也不是玩家水平分。每个失败项扣 20 分，警告项扣 7 分；
真正用于验证建议正确性的指标仍来自教练或玩家盲标。
