# RoundMind CS2 Agent：简历写法

## 一句话版本

设计并实现面向 CS2 Demo 的证据化复盘 Agent：用 demoparser2 将 `.dem` 转为结构化回合事实，
通过 FastAPI + LangGraph 受控编排分析工具，再以质量门禁、决策评分、RAG 和跨场玩家画像生成可追溯训练建议。

## 三条项目经历

- 数据与可靠性：实现 500 MB 分块上传、Demo 头校验、事件去重、SteamID 消歧和质量门禁；支持本地解析模式，避免大文件经过公网。
- Agent 工程：将事实计算与语言生成解耦，Coach Agent 最多选择 6 个白名单工具；仅在低置信、质量异常或高风险判断时触发 Critic，并保留执行轨迹和回合证据。
- 评测与可观测性：建立 14 个 Dust2 决策边界回归场景，当前 14/14 通过；覆盖 17 个预定义边界值和 9/9 个运行阶段，并提供 Coach-only / Coach+Critic A/B 报告接口。

## 指标的正确口径

上述 14/14 是工程回归结果，不是线上泛化准确率；17/17 是评测集场景值覆盖，不是全部 CS2 情况。
在没有 verified Demo、盲测人工动作标注和同一玩家前后测之前，不要写“准确率 100%”“胜率提升”或“分数上涨”。
运行 `python -m chapter07_cs2_coach.evaluation_report` 可复现当前指标，报告中的 `not_evaluated` 列表记录证据边界。

## 面试时的重点

1. 为什么不把原始 Demo 直接发给大模型：大文件成本高、事实不可审计，且模型不应计算比分和交火。
2. 为什么先做质量门禁：解析缺失若被当成玩家弱点，会把错误放大到画像和训练计划。
3. Critic 解决什么问题：它不是重复解析，而是对命中门槛的结论做独立证据复核；A/B 先测资源与路径差异，效果要靠人工标签验证。

## 真实效果如何补齐

为同一 SteamID 保存匿名的复盘前后窗口，至少记录目标行为的基线、训练周期、复测场次和变化；再把系统候选动作交给盲测标注者，报告 Top-1、Top-2、置信度分层和不确定样本。只有这两类数据完成后，才把朋友的反馈写成可验证的效果指标。
