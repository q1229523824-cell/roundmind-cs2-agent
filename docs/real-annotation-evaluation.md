# 真实 Demo 标注与准确度评测

## 为什么需要独立标注

规则能够通过自己设计的边界测试，并不等于能够正确评价真实比赛。真实评测必须满足：

- 标注者在不修改评分公式的情况下评价场景；
- 保留“无法判断”，不能强迫每个场景只有一个正确答案；
- 同时抽取高、中、低风险场景，不能只验证系统最自信的结果；
- 评分修改后在同一批冻结样本上重新计算指标。

## 标注包包含什么

每个场景包含回合号、Tick、地图、接战事实、系统预测和空白人工标签。导出时不会写入：

- 玩家昵称；
- SteamID；
- 原始比赛 ID；
- Demo 路径或 Demo 文件；
- 队伍和对手名称。

`source_fingerprint` 和 `case_id` 是不可逆的短哈希，只用于同一批样本的稳定追踪。

## 人工标签

`human_annotation.verdict` 支持：

- `high_risk`：现有信息足以判断接战条件明显不合理；
- `review`：存在值得复盘的风险，但不能直接判定严重错误；
- `reasonable`：在当时条件下基本合理，即使最终死亡；
- `uncertain`：缺少录像视线、烟雾、时间或敌人信息，无法可靠判断。

`reason_tags`、`better_action` 和 `note` 用于记录理由，不参与第一版自动指标。

## 当前指标

- `coverage`：已标注比例；
- `exact_agreement`：系统三级判断与人工标签完全一致率；
- `mean_ordinal_error`：合理、复盘、高风险三个等级的平均距离；
- `high_risk_precision/recall`：高风险判断的精确率与召回率；
- `top3_high_risk_precision`：系统最高三项中人工认可为高风险的比例；
- `uncertain_cases`：人工认为信息不足的数量；
- `confusion`：逐类别混淆计数。

在没有人工标签时，准确率相关字段必须为 `null`，禁止显示虚假的 0% 或 100%。
