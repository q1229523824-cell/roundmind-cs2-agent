# Dust2 RAG 学习说明

## 为什么先做本地混合检索

本项目当前只有一张地图和少量知识。直接引入向量数据库会增加依赖、部署内存和调试成本，
却不一定提高这 10 条知识的召回效果。因此第一版采用“元数据过滤 + 关键词计分”：

1. 只检索与比赛地图一致的知识；
2. 从 Demo 接战快照提取阵营与点位；
3. 从用户问题和确定性证据识别主题；
4. 对点位、主题和关键词命中分别计分；
5. 只向报告提供前三条知识，并保留知识 ID 与来源。

## 数据流

```text
Demo 原始事件
  └─> MatchRecord / EngagementRecord（事实层）
       └─> 六个确定性分析工具（诊断层）
            └─> reviewer（事实校验与排序）
                 └─> knowledge_retriever（战术知识检索）
                      └─> reporter（事实 + 建议 + 来源）
```

知识库不会修改 K/D/A、回合、距离或补枪结果，也不会把一般战术原则描述成这场比赛已经发生的事实。

## 面试表达

- “我把事实计算与生成建议分离，降低了大模型幻觉对比赛统计的影响。”
- “小数据阶段用元数据和关键词建立可解释基线，先做检索评测，再决定是否引入向量数据库。”
- “每个检索结果都返回稳定 ID、匹配主题、分数和来源，方便离线评测与线上排错。”
- “检索接口与存储实现解耦，未来可替换 FAISS 或 pgvector，而不需要改 API 返回结构。”

## 下一阶段评测

准备 20—30 个真实 Dust2 场景作为查询集，每条人工标注应命中的知识 ID，计算：

- Recall@3：正确知识是否出现在前三条；
- MRR：第一条正确知识的排序是否足够靠前；
- 建议一致性：建议是否与阵营、点位、人数局势冲突；
- 无依据率：报告是否出现既没有 Demo 证据、也没有知识来源支撑的战术断言。
